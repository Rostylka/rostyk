NBA Teams API – Complete Model
Below is a complete specification for an API to catalogue NBA teams, players, and games, following both functional and non-functional requirements, while applying the Richardson Maturity Model and addressing caching, pagination, authentication, and error handling.
________________________________________
Functional Requirements
Entities
1.	Team:
o	Represents an NBA team.
o	Fields:
	id (int) — Unique identifier for the team.
	name (string) — Name of the team.
	city (string) — City where the team is based.
	arena (string) — Home arena name.
	abbreviation (string) — Abbreviation of the team (e.g., "LAL").
	established (int) — Year the team was founded.
	conference (string) — The conference (Eastern/Western).
	division (string) — The division (e.g., "Atlantic").
	logo_url (string) — URL for the team’s logo image.
2.	Player:
o	Represents an NBA player.
o	Fields:
	id (int) — Unique identifier for the player.
	name (string) — Player's full name.
	team_id (int) — The ID of the team the player belongs to.
	position (string) — Position of the player (e.g., "Guard", "Forward").
	height (string) — Height of the player (e.g., "6'7").
	weight (int) — Weight of the player in pounds.
	birthdate (string) — Birthdate of the player (in ISO format).
	college (string) — College the player attended.
	nationality (string) — Nationality of the player.
3.	Game:
o	Represents an NBA game.
o	Fields:
	id (int) — Unique identifier for the game.
	home_team_id (int) — ID of the home team.
	away_team_id (int) — ID of the away team.
	date (string) — Date and time of the game (in ISO format).
	location (string) — The location of the game (home arena or neutral).
	score_home (int, nullable) — Score of the home team.
	score_away (int, nullable) — Score of the away team.
________________________________________
Operations
1.	Teams:
o	GET /teams: Retrieve a list of all NBA teams, with optional filters.
	Query Params: conference, division, page, per_page.
	Response:
	200 OK: List of teams in JSON format.
	400 Bad Request: Invalid filter or pagination parameters.
o	GET /teams/{id}: Retrieve a specific team by ID.
	Response:
	200 OK: Team details in JSON format.
	404 Not Found: Team not found.
o	POST /teams: Create a new NBA team.
	Request Body: JSON object representing a team.
	Response:
	201 Created: Team successfully created.
	400 Bad Request: Invalid data in the request body.
o	PUT /teams/{id}: Update an existing team.
	Request Body: JSON object with updated team details.
	Response:
	200 OK: Team successfully updated.
	400 Bad Request: Invalid data in the request body.
	404 Not Found: Team not found.
o	DELETE /teams/{id}: Delete an NBA team.
	Response:
	200 OK: Team successfully deleted.
	404 Not Found: Team not found.
2.	Players:
o	GET /players: Retrieve a list of all players, with optional filters.
	Query Params: team_id, position, page, per_page.
	Response:
	200 OK: List of players in JSON format.
	400 Bad Request: Invalid filter or pagination parameters.
o	GET /players/{id}: Retrieve a specific player by ID.
	Response:
	200 OK: Player details in JSON format.
	404 Not Found: Player not found.
o	POST /players: Create a new player.
	Request Body: JSON object representing a player.
	Response:
	201 Created: Player successfully created.
	400 Bad Request: Invalid data in the request body.
o	PUT /players/{id}: Update an existing player's information.
	Request Body: JSON object with updated player details.
	Response:
	200 OK: Player successfully updated.
	400 Bad Request: Invalid data in the request body.
	404 Not Found: Player not found.
o	DELETE /players/{id}: Delete a player.
	Response:
	200 OK: Player successfully deleted.
	404 Not Found: Player not found.
3.	Games:
o	GET /games: Retrieve a list of scheduled games, with optional filters.
	Query Params: team_id, date_after, page, per_page.
	Response:
	200 OK: List of games in JSON format.
	400 Bad Request: Invalid filter or pagination parameters.
o	GET /games/{id}: Retrieve details of a specific game by ID.
	Response:
	200 OK: Game details in JSON format.
	404 Not Found: Game not found.
o	POST /games: Schedule a new game between two teams.
	Request Body: JSON object representing the game details.
	Response:
	201 Created: Game successfully scheduled.
	400 Bad Request: Invalid data in the request body.
o	PUT /games/{id}: Update an existing game (e.g., update scores after a game).
	Request Body: JSON object with updated game details.
	Response:
	200 OK: Game successfully updated.
	400 Bad Request: Invalid data in the request body.
	404 Not Found: Game not found.
o	DELETE /games/{id}: Delete a game (e.g., if canceled).
	Response:
	200 OK: Game successfully deleted.
	404 Not Found: Game not found.

Non-Functional Requirements
Performance & Scalability
•	Caching: Use HTTP caching (e.g., ETag, Last-Modified headers) for frequently accessed endpoints (e.g., teams and players list).
•	Pagination: All endpoints that return lists of items (teams, players, games) should implement pagination with page and per_page query parameters to handle large datasets efficiently.
•	Rate Limiting: Limit the number of requests to the API per minute to avoid abuse.
Security
•	Authentication: Use Bearer Tokens (OAuth 2.0) for authentication.
o	Authorization Header: Authorization: Bearer {token}
o	API endpoints must check the validity of the token before proceeding with requests.
o	Admin and user roles should be assigned to control access to certain endpoints (e.g., only admins can create or delete teams).
•	Input Validation: Validate input data (e.g., correct player height format, valid team name) to prevent invalid data from being processed.
Reliability
•	Error Handling: All API endpoints should return standard HTTP status codes to indicate success or failure:
o	200 OK: The request was successful.
o	201 Created: The resource was successfully created.
o	400 Bad Request: The request was malformed or missing required data.
o	404 Not Found: The requested resource (team/player/game) does not exist.
o	500 Internal Server Error: A server error occurred during processing.
o	401 Unauthorized: Missing or invalid authentication token.
o	403 Forbidden: The authenticated user does not have permission for the requested operation.
•	Logging: All critical operations (e.g., user authentication, team creation) should be logged to help with debugging and troubleshooting.
________________________________________
Richardson Maturity Model
This API adopts Level 3 of the Richardson Maturity Model:
•	HTTP Methods: The API uses proper HTTP methods for each operation: GET, POST, PUT, and DELETE to reflect the standard RESTful actions for retrieving, creating, updating, and deleting resources.
•	Stateless: The API is stateless; each request should contain all the necessary information (including authentication) to process the request. The server does not maintain any state between requests.
•	Hypermedia as the engine of application state (HATEOAS): Links to related resources (e.g., team and player links within responses) should be included to guide the client on possible next actions.
________________________________________
Caching
•	Teams and Players List: Cache the results for GET /teams and GET /players for up to 1 minute.
•	Game Schedules: Cache game schedules (GET /games) for up to 30 minutes.
•	Use appropriate cache control headers (Cache-Control: public, max-age=60) for endpoints that can be cached.
________________________________________
Pagination
All endpoints returning lists of items (teams, players, and games) should be paginated. For example:
•	GET /teams: Add page and per_page query parameters.
o	Example: GET /teams?page=1&per_page=20
•	GET /players: Add page and per_page query parameters.
o	Example: GET /players?team_id=1&page=1&per_page=20
•	GET /games: Add page and per_page query parameters.
o	Example: GET /games?page=1&per_page=20
________________________________________
Authentication
•	Use OAuth 2.0 for user authentication. The Bearer Token should be passed in the Authorization header for each API request.
•	Example:
o	Request: GET /teams
o	Headers: Authorization: Bearer {token}
